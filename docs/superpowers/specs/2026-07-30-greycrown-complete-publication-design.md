# 灰冠王国完整作品集仓库发布设计

日期：2026-07-30

## 目标

把现有的游戏 AI 功能切片升级为完整、可运行、可审查的灰冠王国作品集仓库。仓库继续使用现有地址和非强制更新方式，保留当前公开提交历史，不导入原开发仓库历史。

“完整”指游戏运行闭包完整，而不是把开发机器上的所有文件原样公开。招聘方克隆仓库后，应能查看并运行 Godot 客户端、查看全部运行时资源、执行测试，并独立构建 TypeScript 服务端。

## 发布结构

### 完整客户端

公开以下 Godot 项目内容：

- `client/project.godot` 和 `client/export_presets.cfg`
- `client/scripts/`：全部运行时代码，包括战斗、锻造、城市、NPC、AI GM、音频和 UI
- `client/scenes/`：全部运行场景
- `client/data/`：全部游戏配置和内容数据
- `client/dialogic/`：全部对话时间线
- `client/tests/`：完整自动化与手动测试源码
- `client/assets/`：全部运行时资源，包括 229 张 PNG 美术和 7 首 BGM
- Godot 正确解析资源所需的 `.uid` 和 `.import` 文件

不加入额外运行截图。README 使用文字说明项目能力，游戏实际读取的美术资源本身保留在仓库中。

### 服务端

公开 `server/src/`、测试、`package.json`、锁文件、TypeScript/Vitest 配置和必要启动说明。`node_modules/`、`dist/` 和本机缓存由使用者通过 `npm ci` 重新生成，不进入 Git。

旧的 `server/index.js`、`server/server.py` 和对应批处理入口不属于当前权威服务端，不纳入公开仓库，避免与 TypeScript 服务端混淆。

### 公开文档

README 将从“功能切片”改为“完整游戏项目”，说明核心玩法、AI GM 边界、目录结构、运行步骤、测试命令、当前限制和 AI 辅助开发事实。保留已有架构、配置、面试和验证文档，但修正与完整仓库不一致的描述。

## 明确排除范围

以下内容不属于游戏运行闭包，不公开：

- 原开发仓库的 `.git/` 历史
- `key.txt`、`.env`、真实 API Key、Token、Cookie 和私有配置
- `.godot/`、存档、日志、测试结果、浏览器缓存和包管理器缓存
- `node_modules/`、`dist/`、Godot 导出产物、Windows 可执行包和 `.pck`
- `references/` 中的外部参考游戏、压缩包、可执行文件和反编译材料
- `output/imagegen/` 中的生成过程、失败样本、提示词和中转站配置
- 答辩 PPT、课程作业、私人工作日志、Agent 工具目录和本机开发记录
- `music/` 中与 `client/assets/audio/bgm/` 重复的原始文件

## 资源与许可证

运行时美术和 BGM 随游戏公开，因为缺少它们会破坏可运行闭包。仓库使用作品集用途声明，不因公开可见而自动授予第三方复制、再分发或商业使用权。

README 和资源说明将披露：

- 开发过程使用了 AI 辅助编程
- 部分运行时美术由生成式 AI 辅助制作
- 7 首 BGM 是项目运行时音乐资源
- `client/scripts/battle/phigros/phigros_lane/` 含基于 `godot-phigros` 修改的 MPL-2.0 文件

MPL 文件保留原作者、来源、文件头和修改说明，并在仓库中提供完整 MPL-2.0 许可证文本。项目作品集声明不能覆盖第三方许可证。

## 导出与脱敏流程

1. 原项目只读，按白名单导出当前工作树，而不是从旧提交或旧发布包复制。
2. 先导出到新的临时校验目录，不直接覆盖公开仓库。
3. 对临时目录执行文件类型、大小、符号链接、密钥、PII、本机路径和二进制元数据扫描。
4. 在临时目录中修正项目名、可移植路径、示例配置和测试用模拟 Key。
5. 将验证通过的文件同步到现有公开仓库，并保留已有的公开安全加固与作品集文档。
6. 复查 Git 暂存区，确认没有从原仓库带入历史或忽略文件。

公开配置只允许 `.env.example` 或等价模板，所有需要密钥的功能默认关闭或退化到离线路径。使用者必须自行提供环境变量或本地配置。

## 验证标准

提交和推送前必须满足：

- 完整性检查确认白名单中的客户端、服务端、测试和运行时资源均已复制
- 所有公开文件小于 25 MiB；当前运行时资源单文件最大约 5 MiB
- 隐私扫描对真实密钥、私人邮箱、手机号、用户目录和原项目绝对路径返回零发现
- 仓库不包含 `.env`、存档、数据库、日志、可执行文件、`.pck` 或压缩包
- Godot 4.6 能从公开仓库导入并解析项目
- Godot 完整单元测试通过，或记录可复现且与导出无关的明确阻塞项
- TypeScript 服务端执行 `npm ci`、`npm test` 和构建检查
- WebQA 从公开仓库执行；生成截图只作为本地验证产物，不提交到仓库
- Git 历史只包含已脱敏的作品集提交，推送使用普通 fast-forward，不使用 force push

## 故障处理

任一安全扫描、完整性检查、测试或构建失败时停止在本地，不提交、不推送。修复只发生在公开副本或导出工具中，原项目保持不变。

如果普通 Git 推送因远端仓库体积限制失败，保留本地提交并报告具体错误，不自动改用 Git LFS，也不重写远程历史。采用 LFS 或拆分资源需要重新取得用户确认。

## 完成标准

现有 GitHub 仓库展示完整灰冠王国项目，README 不再声称它只是 AI GM 切片；克隆仓库后无需私有文件即可运行离线游戏、查看全部美术与 BGM、执行 Godot 测试并构建服务端。公开历史中不存在真实凭据、私人数据、外部参考项目或原开发仓库历史。
